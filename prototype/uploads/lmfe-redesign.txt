1 · Master design prompt
Paste the block below into the design tool as one prompt. It assumes the tool already holds the UI
generated from IA v1 and instructs it to restructure and re-skin.
CONTEXT
You are updating the Delhivery LM-FE rider app you previously generated from my information architecture.
Apply every change below. Keep what already works; restructure and re-skin the rest. Target user: delivery
riders in Indian Tier 1–3 cities, often first-time smartphone-heavy users, riding one-handed, outdoors, in
sunlight, sometimes offline.
VISUAL DIRECTION — TARMAC DESIGN SYSTEM (fixes: plain UI, wrong error colors, inconsistent
icons)
1. Color: Delhivery red #ED1B36 is reserved for primary CTAs, the active nav tab, and brand moments;
pressed state #A31226. Ink #16171B for text, chalk #FBFAF8 surfaces layered on white cards. Semantic colors
only for status: green = success, amber = advisory, red = error/blocked. Errors are ALWAYS red with inline
helper text — never yellow.
2. Type and touch: 16sp minimum body, 20sp+ for amounts and counts, 48dp minimum tap targets, AA+
contrast for sunlight. Numbers (earnings, COD amounts, counts) always in a tabular bold style.
3. Components: 12px-radius cards with 1px hairlines, tinted tag pills (COD amber, prepaid green, priority red,
flash violet, REPL teal), one consistent 24px outline icon set, icons always paired with labels for primary
actions.
4. Signature element: kilometre-stone progress markers (Tarmac motif) for all steppers and progress —
onboarding wizard, docs, day progress. Subtle, geometric, brand red.
5. Motion: 150–250 ms ease-out on state changes and progress only; success check-draw <= 400 ms. No
bouncing, no mascots, nothing childish. Skeleton loaders (never blank spinners) with step captions for anything
> 1 s.
GLOBAL STRUCTURE (fixes: no primary nav, hidden menu, orientation)
6. Add a persistent 4-tab bottom nav across the FE app: Home · Shipments · Summary · Earnings. Active tab in
red. Remove navigation from the hamburger; the menu keeps only profile, language, help, safety, logout.
7. Add a language selector at first launch and in the menu (English, Hindi, Kannada, Tamil, Telugu, Marathi,
Bengali to start). All strings localizable; icon+label patterns throughout; optional voice guidance toggle for key
flows.
8. Inline education pattern: small tappable '?' chips beside any jargon — FWD, RVP, Direct, Priority vs Flash,
LastMile Pro, auto-start permission — opening a 2-line plain-language sheet with an illustration.
9. Offline-first: queue POD, status and payment confirmations locally with a sync badge; optimistic UI. App
updates download in the background and install only off-duty — never block a rider mid-delivery; show a
deferred 'update ready' banner instead.
SCREEN 1 — LANGUAGE SELECT (new)
First-launch screen: language grid with native-script labels, continue CTA. Reachable later from menu.
SCREEN 2 — LOGIN + OTP (redesign; fixes: ghost text, edit number, small OTP boxes, silent PIN
setup)
10. Phone field with +91 prefix and ghost text '98765 43210', numeric keypad, live 10-digit validation.
11. OTP screen shows the number with an 'edit' affordance returning to the field. Six 48dp OTP boxes,
auto-advance, auto-read consent. Resend with visible timer. Attempt-lock errors in red with a countdown chip.
12. New users get an explicit interstitial — 'You're new here. Next: set a 4-digit PIN to secure your account' —
before PIN setup. Returning users go straight to PIN entry.
SCREEN 3 — UNIFIED ONBOARDING WIZARD (restructure; fixes: two disjoint flows, inconsistent
stepper, DL field, PAN–Aadhaar, progressive CTAs)
13. Merge the partner-app application and FE document setup into ONE linear guided wizard: Mobile ->
Aadhaar -> Vehicle -> Payout (bank) -> Location -> Driving licence -> PAN. Kilometre-stone stepper with
percent complete and 'save and resume later'.

14. Every step uses the same two-beat pattern: capture -> confirm. No mixing of upload steps and form steps
without warning; each step states what is needed and why, up front.
15. Driving licence field relabelled 'Driving licence (15-character code)' with an alphanumeric input mask (e.g.
MH12 20180054797), format hint, and DOB-must-match-Aadhaar note shown BEFORE input.
16. PAN step checks Aadhaar-link status and, when unlinked, opens a 'Not linked? Here's how' help sheet with
steps and a retry — plain-language copy, no dead ends.
17. All wizard CTAs are sticky full-width bottom buttons, always reachable one-handed; disabled states carry a
reason line above the button.
SCREEN 4 — HANDOFF / INSTALL VERIFY (fixes: FE app 'downloaded but not accessible')
18. After the wizard, the handoff screen verifies the FE app via deep link: primary CTA 'Open FE App' (not
'download'); if the app isn't resolvable it falls back to the store with install-state detection and a
troubleshooting line. Keep the workplace card (DC contact, distance, directions).
SCREEN 5 — HOME (redesign; fixes: hierarchy, single CTA, unexplained concepts)
19. Reorder: (1) pending-action stack — document verification, unbooked slots, cash due, update ready — as
red-edged task cards; (2) next-best-action card ('Book tomorrow's slot', 'Start delivering'); (3) today's slot +
projected earnings; (4) banners last. Greeting shrinks to a single line.
20. Every concept on this page (LastMile Pro, auto-start permission, league) gets a '?' education chip. Bottom
nav present.
SCREEN 6 — EARNINGS (new tab; fixes: payout visibility, filters, incentive chart, productivity)
21. Pending vs completed payouts as two totals with dates; week / month / year filter; per-day list.
22. Incentive milestone chart with labelled axes and rupee values at each stone; 'How productivity is
calculated' expandable formula breakdown; earnings-per-shipment transparency.
SCREEN 7 — PUNCH-IN (resequenced; fixes: selfie appears late)
23. The helmet selfie moves to punch-in — before any shipment work, one selfie gates the duty session
(checklist: helmet, lit, T-shirt). Remove selfie from the mid-delivery flow entirely.
SCREEN 8 — DISPATCH (fixes: hierarchy, loading, navigation gaps)
24. 'Create dispatch' and 'Punch out' become equal-weight side-by-side actions. Scanning shows a live package
count. Loading uses skeletons with step captions ('Fetching assignments 2/3') so long waits read as progress,
and the route from Home -> duty -> dispatch is a single visible path.
SCREEN 9 — ROUTE VIEW (new; fixes: no route optimization)
25. After dispatch: an ordered stop list optimized by proximity — total distance and ETA on top, numbered
stops, drag-to-reorder, 'Start route' launching turn-by-turn per leg, auto-advance to the next stop after each
completion.
SCREEN 10 — SHIPMENTS LIST (redesign; fixes: information hierarchy, filters, iconography)
26. Each card leads with what riders decide by: packages count, distance from current position, earning for the
stop, then consignee + short address. Type tags use the tinted pill set with a one-tap legend; the lightning icon
is defined once (priority) and never reused.
27. Filter chips under the tabs: Priority, Flash, COD, Prepaid, Nearby. List defaults to route order. Tab icons
re-drawn to consistent size and weight.
SCREEN 11 — ORDER DETAIL (redesign; fixes: map mismatch not actionable, checks clutter)
28. Consolidate the three checks into one status strip (calls, geofence, payment) with a fix-action on any failing
check.
29. Address accuracy module: customer-provided landmark line, 'Flag wrong location' action that captures the
corrected pin for ops, and pre-arrival call / WhatsApp chat shortcuts — the app helps resolve mismatch instead
of only flagging distance.
SCREEN 12 — PAYMENT (redesign; fixes: COD warning, UPI CTAs, payer label, split logic)

30. One payment path per order: an explicit choice screen — Cash OR UPI QR — as two large cards; no
simultaneous split. Chosen method opens a focused screen with a real full-width CTA. 'Payer' renamed
'Customer pays'. Success and pending-retry states are full-screen and unambiguous; cash path gets a
confirm-amount keypad.
SCREEN 13 — PROOF OF DELIVERY (redesign; fixes: self-signature loophole, reluctant customers)
31. Order: recipient -> proof. Signature switches to a customer-facing flip mode (rotated canvas + 'hand the
phone to the customer' prompt) with random photo audits to close the self-sign loophole; QR/code-verified
orders keep the auto-verified fast path.
32. When a customer declines signature/photo: alternative proofs — delivery-code confirmation or doorstep
parcel photo (no face) — so prepaid deliveries never stall on consent.
SCREEN 14 — NSL / CANCELLATION (redesign; fixes: OTP not arriving, cancel failing, no refund
status)
33. Verification fallback ladder: WhatsApp OTP -> SMS OTP -> in-app customer link, each with resend timers; if
all fail, TL-override path with mandatory audio note. Cancel actions get explicit failure states with retry +
support escalation instead of failing silently.
34. Post-cancellation status screen: what happens next for the rider, automatic refund-initiated notification to
the customer, and the shipment's new state on the route.
SCREEN 15 — SUMMARY (redesign; fixes: POD contradiction, unclear metrics)
35. POD quality is enforced at capture (blur/dark detection before submit). Any post-delivery POD flags appear
as actionable tasks — what is wrong, how to fix, deadline — never as unexplained accusations. Progress adds a
time-of-day breakdown.
SCREEN 16 — END OF DAY (new; fixes: reconciliation, cash dead end)
36. Guided punch-out sequence: pending collections review -> cash submission (day total, DC handover
reference, TL confirm, mismatch flag) -> flagged-issue review -> punch out with day recap (delivered, earned,
streak). This is the only path to punch out once cash was collected.
SUCCESS METRICS THESE CHANGES TARGET
Onboarding completion rate, first-week attrition, document verification error rate, support tickets in week 1,
dispatch creation time, first-attempt delivery rate, fake-attempt rate, COD collection success, end-of-day
reconciliation time, rider NPS.
